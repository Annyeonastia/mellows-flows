# AI Scout — интерактивный прототип. Handoff

Проект: `~/Documents/Claude/ai-scout-prototype`
Figma: <https://www.figma.com/design/1jDVy4XVyDuulgoKc6P2Lv/AI-Scout>
Дизайнер: Анастасия. Общается по-русски, код и интерфейс — на английском.

```bash
cd ~/Documents/Claude/ai-scout-prototype
npm run dev      # http://localhost:5173
npm run build    # tsc -b && vite build — держать зелёным
```

Дев-ярлыки в адресной строке: `#pool` открывает таблицу сразу, минуя импорт;
`#live` — реквест, который уже поработал (все матчи, состояние Live Request);
`#gallery` показывает иллюстрации отдельно. Ярлык читается при монтировании —
после смены хеша нужен `reload`.

Стек: Vite + React + TypeScript, **чистый CSS с переменными**. Tailwind не ставить.

**Деплой работает.** Репозиторий `Annyeonastia/mellows-flows`, ветка `main`.
Пуш в `main` запускает `.github/workflows/deploy.yml` и раскатывает
<https://annyeonastia.github.io/mellows-flows/> (сборка с `DEPLOY_BASE=/mellows-flows/`,
прогон ~40 секунд). `dist` в `.gitignore`. Рядом лежит `netlify.toml` — тот же
`npm run build`, но с базой `/` и SPA-редиректом; подключён ли сайт в Netlify,
из репозитория не видно.

## Решения, которые уже приняты — не переигрывать

- **Ширина 1280**, не 1440. В переменных Figma `Width: 1280`, все фреймы такие. Подтверждено дизайнером
- **Шрифты** Suisse Int'l и PP Neue World лежат в `public/fonts`, скопированы из системных. Подключены через `@font-face`
- **Таблица засеяна 20 строками** из макета (`src/data/contractors.ts`), импорт добавляется сверху. Иначе после первого импорта нечего скроллить
- **`choose files` подставляет набор файлов из макета** — чтобы демо было предсказуемым. Реальный drag & drop работает по-настоящему с валидацией
- **Экран `Error` в Add emails — только для файлов.** Для пустого и невалидного ручного ввода — disabled-кнопка и inline-валидация
- **Заголовок таблицы не липкий по вертикали** — в макете `Vertical Scroll` он уезжает вместе со строками
- **Шапка страницы `position: absolute`** над скроллящимся контентом — так получается блюр строк под ней
- **Модалки не размонтируют таблицу.** Фильтры, скролл, выделение и поиск сохраняются. Это отдельно проверено, не сломать
- **Профиль — отдельный модуль**, `screens/ContractorProfile.{tsx,css}` + `data/profile.ts`. Макеты `28868-140728` / `28933-248988` черновые, поэтому вся геометрия и цвета живут в этих файлах: под чистовые макеты переписываются только они. Ссылки, скиллы и лента Activity выводятся из данных строки — в модели `Contractor` их нет
- **Заметка в шторке — это `notes` строки таблицы.** Правка сразу видна в колонке Notes, лимит 256
- **Снеки идут через стор** (`notify` / `toast`), а не через локальный стейт экрана: их зовут и шторка, и шапка
- **Флоу `Generate request` (AIHR-614 + AIHR-613) собран:**

  ```text
  Contractor Pool → Generate request → попап → New Request (реквест создан)
        ├ ⋮ → Edit request → ← или Publish changes → обратно в реквест
        └ клик по кандидату → шторка → Invite → X → тот же список
  ```

- **`Edit request` правит уже существующий реквест, а не создаёт его.** Это не
  шаг между попапом и реквестом: кнопка называется `Publish changes`, а алерт
  обещает «all your AI Matches **will keep**» — сохранить можно только те матчи,
  которые уже есть. Поэтому `Generate request` в попапе сразу создаёт реквест,
  а Edit открывается из меню ⋮ на странице реквеста. Меню ⋮ есть в макетах, это
  единственное место с «ещё действиями», ничего не выдумано
- **Черновик (`requestDraft`) живёт в сторе, а не в компоненте.** Закрытие попапа
  его сбрасывает — как отмена в Upload CVs сбрасывает файлы
- **Edit собран по фреймам `[by M]`** (`28328:286048` / `28328:286942`) для **обеих**
  веток. Взять основной фрейм для public и `[by M]` для private нельзя — это два
  разных дизайна одного экрана в одном флоу
- **Чипы покрытия в попапе** (`lib/requestCoverage.ts`) — не ИИ, а поиск по ключевым
  словам. Правила выверены по фрейму `Filled`: строка из макета зажигает ровно
  role, time commitment, budget, location. Меняя правила, проверять этот случай
- **Приватность считается от данных, а не от текста макета.** Баннер сам считает,
  сколько матчей скрыто, вместо зашитого в макет числа
- **Иллюстрации остаются 3x PNG.** Вектор не нужен: «нам надо просто показать».
  `delete-profile.png`, `send.png`, `loading.gif` — трогать не надо
- **Нижнюю пагинацию дублируем** — она есть в макетах, значит делаем (ещё не сделано)

## Грабли, на которые уже наступали

- **Не собирать иллюстрации из отдельных векторов.** Компоненты лежат в подключённой библиотеке, MCP их ноды не отдаёт. Попытка склеить `img/delete_profile` из 30 SVG с масками дала визуально сломанный рисунок. Рабочий способ: `download_assets` по фрейму с `defaultScale: 3`, затем вырезать нужный кусок через `sips -c H W --cropOffset TOP LEFT`
- **Анимация загрузки — это GIF-заливка.** `get_design_context` отдаёт только первый кадр как PNG, `get_motion_context` пустой. Настоящий файл достаётся через `download_assets` → `rawImages` (там `format: "gif"`). Лежит в `src/assets/illustrations/loading.gif`, 153 кадра
- **Ноды внутри инстансов компонентов не адресуются** ни `get_design_context`, ни `get_screenshot`. Цвета и мелкие иконки проще снимать пиксельно: положить PNG в `public/`, прочитать через canvas в `javascript_tool`
- **`download_assets` обрезает выдачу на 20 SVG** — на больших фреймах бесполезен для иконок
- **zsh не разбивает строку на слова.** В циклах использовать массивы: `ids=(a b c); for id in "${ids[@]}"`. И `grep --include=*.tsx` без кавычек zsh тоже съедает — писать `--include="*.tsx"`
- **Скриншоты из Browser-панели приходят уменьшенными и иногда запаздывают.** Для проверки надёжнее замерять DOM через `javascript_tool`, а не смотреть картинку
- **`getComputedStyle` врёт, пока вкладка скрыта.** При `document.visibilityState === "hidden"` браузер не пересчитывает стили: computed-значения и `getBoundingClientRect` отдают состояние на момент последней отрисовки, и даже инлайновый `!important` не виден. Лечится одним `computer{action:"screenshot"}` — он заставляет отрисовку, после него замеры честные. Структура DOM (классы, `textContent`, `matches()`) при этом всегда актуальна
- **React-стейт не успевает к синхронному чтению.** После `.click()` результат читать в отдельном вызове или через `await new Promise(r => setTimeout(r, 60))`
- **Порт 5173 может быть занят соседней сессией.** `vite.config.ts` читает `PORT`, в `.claude/launch.json` стоит `autoPort: true`
- **React не ловит синтетический `mouseenter`** — для проверки тултипов слать `mouseover`/`mouseout` с `bubbles: true`
- Иконки `✓` `✗` `⋮` — PNG 3x, вырезаны из рендера таблицы, белый фон убирается `mix-blend-mode: multiply`

## Открытые вопросы к дизайнеру

1. **Копирайт тумблера в попапе не меняется.** И в `Off`, и в `On` написано
   «Private matching is Off…». В Edit тот же тумблер меняет текст правильно
   (`Private matching is on. Matched only against My Pool…`), в попапе — нет.
   Оставлено как в макете по прямому указанию, но это баг макета
2. **Счётчик `0 / 256`** в макете не меняется и в заполненном состоянии.
   В коде считает по-настоящему
3. **Бейдж `AI matches 3`** при двух карточках и подписи «Total: 2 matches».
   В коде число берётся из данных
4. **Как пользователь переключается между `New` и `Live Request`** — в макетах
   управления нет
5. **Куда ведёт `Close` на Edit.** В шапке Edit только стрелка назад, крестика нет
   ни в основных фреймах, ни в `[by M]`. Сейчас стрелка = `Back` в попап
6. **Меню под `AI Scout` — нужен номер ноды.** В макетах не нашёл. Пока его нет,
   кнопка остаётся без выпадашки — пункты не выдумывать.
   Меню под аватаром делать по варианту `profileDropdown` во фрейме `21347-37062`:
